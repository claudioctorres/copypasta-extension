## 1. MV3 `content_scripts` manifest keys

Sources: https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts (A) · https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts (B)

- [V] `run_at` ∈ `document_start | document_end | document_idle`; default idle. (A)
- [V] `document_start`: "Scripts are injected after any files from `css`, but before any other DOM is constructed or any other script is run." (B)
- [V] `all_frames`: "Defaults to `false`, meaning that only the top frame is matched." (A)
- [V] `match_about_blank`, `match_origin_as_fallback` (about:/data:/blob:/filesystem: frames created by a matching origin). (A, B)
- [V] `world`: "Defaults to `"ISOLATED"`". (A)
- [V] `css` is injected "before any DOM is constructed or displayed for the page." (B)
- [V] Scripting API versions: `matchOriginAsFallback` Chrome 119+, `world` on RegisteredContentScript 102+, register/get/unregister/update 96+. https://developer.chrome.com/docs/extensions/reference/api/scripting

## 2. `chrome.scripting.registerContentScripts`

Source: https://developer.chrome.com/docs/extensions/reference/api/scripting (Last updated 2026-09-11)

- [V] "declare the `"scripting"` permission in the manifest plus the host permissions for the pages to inject scripts into. Use the `"host_permissions"` key or the `"activeTab"` permission"
- [V] `id`: "Must not start with a '_' as it's reserved as a prefix for generated script IDs."
- [V] `js`: "injected in the order they appear in this array." `css`: injected "before any DOM is constructed or displayed for the page."
- [V] `allFrames`: "If specified true, it will inject into all frames, even if the frame is not the top-most frame in the tab."
- [V] `persistAcrossSessions`: "Specifies if this content script will persist into future sessions. The default is true."
- [V] `registerContentScripts`: "If there are errors during script parsing/file validation, or if the IDs specified already exist, then no scripts are registered."
- [V] `unregisterContentScripts(filter?)`: "Otherwise, all of the extension's dynamic content scripts are unregistered."
- [V] `StyleOrigin` = AUTHOR | USER; `CSSInjection.origin` "Defaults to `'AUTHOR'`". RegisteredContentScript `css` has no origin field.

## 3. Optional host permissions & user gesture

Source: https://developer.chrome.com/docs/extensions/reference/api/permissions

- [V] "If you want to request hosts that you only discover at runtime, include `"https://*/*"` in your extension's `optional_host_permissions` field."
- [V] "Permissions must be requested from inside a user gesture, like a button's click handler."
- [V] "Chrome prompts the user if adding the permissions results in different warning messages."
- [V] Official sample calls `permissions.request` inside `chrome.action.onClicked`: https://developer.chrome.com/docs/extensions/develop/security-privacy/user-privacy
- [V] Chromium enforcement — extensions/browser/api/permissions/permissions_api.cc: `"This function must be called during a user gesture"`; `if (!user_gesture() && !ignore_user_gesture_for_tests && ...) return RespondNow(Error(kUserGestureRequiredError));`
- [V] MDN (Firefox-oriented): "If a user input handler waits on a promise, then its status as a user input handler is lost." https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/User_actions
- Takeaway: call `chrome.permissions.request` before any other `await` in the click handler.

## 4. Isolated worlds, DOM events, DFWP

- [V] Chrome: "Although the execution environments of content scripts and the pages that host them are isolated from each other, they share access to the page's DOM." (B)
- [V] DOM Standard https://dom.spec.whatwg.org/#concept-event-listener-inner-invoke: "If event's stop immediate propagation flag is set, then break." / invoke: "If event's stop propagation flag is set, then return." / capture pass over the path "in reverse order" (window first).
- Conclusion: a window-capture listener that stops propagation prevents every later target on the path from being invoked. Only window-capture listeners registered *earlier* still run — hence `document_start`.
- **Don't F*** With Paste** (jswanner/DontFuckWithPaste, master) — all [V] from raw files:
  - manifest: MV3, v3.1, permissions `["storage","tabs"]`, content script on `<all_urls>`, `all_frames: true`, no `run_at` (idle), popup action.
  - content.js: listens to **`copy`, `cut`, `paste` only**, on **`document`**, capture; handler `e.stopImmediatePropagation(); return true;` toggled by message.
  - README: "does not try to prevent a site from also interfering with keyboard shortcuts ... nor ... the "contextmenu" event".
  - Store page: 50,000 users, 4.5★ (26), updated Oct 9 2025, "will not collect or use your data". https://chromewebstore.google.com/detail/dont-f-with-paste/efaagigdgamehbpimpiagfpoihlkgamh

## 5. Event semantics

- [V] MDN stopPropagation: "It does not, however, prevent any default behaviors from occurring". https://developer.mozilla.org/en-US/docs/Web/API/Event/stopPropagation
- [V] UI Events keydown default action: "If the key is associated with a character, the default action MUST be to dispatch a beforeinput event followed by an input event." / "If this event is canceled, the associated event types MUST NOT be dispatched" → typing is a default action; stopping propagation without cancelling keeps it. https://w3c.github.io/uievents/#event-type-keydown
- [V] MDN keydown IME guard: `if (event.isComposing || event.keyCode === 229) return;`
- [V] MDN KeyboardEvent: `code` "ignores the user's keyboard layout"; `metaKey` = ⌘ on Mac.
- [V] Input Events L2: `insertFromPaste`, `insertFromDrop`, `deleteByCut` are cancelable `beforeinput` types. https://w3c.github.io/input-events/
